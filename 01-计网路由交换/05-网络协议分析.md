# 网络协议分析复习要点

## 一、TCP三次握手与四次挥手

### 三次握手（建立连接）

```
客户端 → SYN=1, seq=x          → 服务端     （第1次）
客户端 ← SYN=1, ACK=1, seq=y, ack=x+1 ← 服务端  （第2次）
客户端 → ACK=1, seq=x+1, ack=y+1   → 服务端    （第3次）
```

| 阶段 | 方向 | 标志位 | 关键字段 | 说明 |
|------|------|--------|----------|------|
| 第1次 | C→S | SYN=1 | seq=x | 客户端发起连接请求 |
| 第2次 | S→C | SYN=1, ACK=1 | seq=y, ack=x+1 | 服务端确认并同步 |
| 第3次 | C→S | ACK=1 | seq=x+1, ack=y+1 | 客户端确认，连接建立 |

**为什么需要三次？** 防止已失效的连接请求到达服务端，造成资源浪费。

### 四次挥手（释放连接）

```
客户端 → FIN=1, seq=u          → 服务端     （第1次）
客户端 ← ACK=1, ack=u+1       ← 服务端     （第2次）
客户端 ← FIN=1, ACK=1, seq=w, ack=u+1 ← 服务端 （第3次）
客户端 → ACK=1, ack=w+1       → 服务端     （第4次）
```

**为什么需要四次？** TCP是全双工，每个方向需要单独关闭。
**TIME_WAIT状态：** 等待2MSL，确保最后的ACK到达对方。

## 二、TCP协议特点

| 特性 | 说明 |
|------|------|
| 面向连接 | 通信前需三次握手建立连接 |
| 可靠传输 | 确认重传机制保证数据不丢失 |
| 面向字节流 | 以字节为单位传输 |
| 全双工 | 双方可同时发送数据 |
| 流量控制 | 滑动窗口机制 |
| 拥塞控制 | 慢开始、拥塞避免、快重传、快恢复 |

**TCP vs UDP：** UDP无连接、不可靠、面向报文、尽最大努力交付。

## 三、HTTP请求格式

### 请求报文结构

```
请求行：    方法 URL 版本\r\n
请求头部：  头部字段名: 值\r\n
           ...（多个头部字段）
空行：      \r\n
请求体：    （POST/PUT时携带数据）
```

### 常用请求方法

| 方法 | 说明 |
|------|------|
| GET | 获取资源（参数在URL中） |
| POST | 提交数据（参数在请求体中） |
| HEAD | 只获取响应头 |
| PUT | 更新资源 |
| DELETE | 删除资源 |

### 常见状态码

| 状态码 | 含义 |
|--------|------|
| 200 OK | 请求成功 |
| 301 Moved Permanently | 永久重定向 |
| 302 Found | 临时重定向 |
| 400 Bad Request | 请求语法错误 |
| 403 Forbidden | 禁止访问 |
| 404 Not Found | 资源不存在 |
| 500 Internal Server Error | 服务器内部错误 |

### HTTP特点
- 无状态协议（使用Cookie/Session保持状态）
- 默认端口80，HTTPS默认端口443
- 基于TCP传输

## 四、ARP协议工作原理

### 工作流程

1. **发送方**检查本地ARP缓存，查找目标IP对应的MAC地址
2. **缓存未命中**时，发送ARP请求广播（目的MAC: FF-FF-FF-FF-FF-FF）
3. **广播内容：** "谁拥有IP地址X？请告诉IP地址Y"
4. **目标主机**收到后，以**单播**方式回复ARP应答（包含自己的MAC地址）
5. **发送方**收到应答后，将IP-MAC映射存入ARP缓存

### ARP报文类型

| 类型 | 传输方式 | 说明 |
|------|----------|------|
| ARP Request | 广播 | 请求目标MAC地址 |
| ARP Reply | 单播 | 应答自身MAC地址 |

### ARP安全隐患

| 攻击类型 | 说明 |
|----------|------|
| ARP欺骗 | 攻击者伪造ARP应答，将自身MAC映射到目标IP，截获流量（中间人攻击） |
| ARP泛洪 | 发送大量虚假ARP请求占满交换机MAC表，导致网络瘫痪 |
| 无认证机制 | ARP协议本身缺乏身份验证，容易被利用 |

### ARP相关命令

| 命令 | 说明 |
|------|------|
| `arp -a` | 查看ARP缓存表 |
| `arp -s IP MAC` | 静态绑定IP与MAC |
| `arp -d` | 清除ARP缓存 |

## 五、其他重要协议要点

### ICMP协议
- 用于差错报告和网络诊断
- 包含：差错报告报文、控制报文、请求应答报文
- **不包含**地址解析报文（那是ARP的功能）
- ping命令使用ICMP回送请求/应答
- tracert利用ICMP超时报文追踪路径

### DNS协议
- 默认端口53（UDP查询，TCP区域传输）
- 域名解析过程：本地缓存 → 本地DNS → 根DNS → 权威DNS

### FTP协议
- 使用TCP建立两条连接：控制连接（端口21）、数据连接（端口20）
- 上传使用PUT命令，下载使用GET命令

### IP分片与重组
- **MF标志位=1：** 后续还有分片
- **Fragment Offset≠0：** 该报文是分片的一部分
- **Identification字段：** 同一数据报的所有分片标识相同
- 接收方根据以上信息进行重组

### TCP/IP四层模型

| 层次 | 功能 | 对应协议 |
|------|------|----------|
| 应用层 | 应用服务 | HTTP, FTP, DNS, SMTP, SSH |
| 传输层 | 端到端传输 | TCP, UDP |
| 网络层 | 路由与寻址 | IP, ICMP, ARP |
| 网络接口层 | 物理介质访问 | 以太网协议 |
