## 一、子网划分计算

### 解题步骤

1. **确定需求**：明确需要划分几个子网、每个子网至少需要多少台主机
2. **计算借位数**：从主机位借 n 位，使得 `2^n ≥ 所需子网数`
3. **验证主机数**：剩余主机位为 m，需满足 `2^m - 2 ≥ 每子网所需主机数`
4. **确定新子网掩码**：将原掩码的主机前 n 位变为 1，写出新的子网掩码
5. **计算各子网信息**：
   - 网络号 = 子网起始地址
   - 可分配 IP 范围 = 网络号 + 1 ～ 广播地址 - 1
   - 广播地址 = 下一个子网网络号 - 1

### 示例一：C 类网络子网划分

```
题目：某公司3个部门，每部门60台电脑，使用 C 类网络 212.16.56.0/24
      划分子网，写出新子网掩码、子网2的网络号、可分配IP范围和广播地址。

解答：
  1) 需要3个子网，每子网至少60个IP
  2) 借2位 → 2^2 = 4 ≥ 3（满足子网数）
  3) 剩余主机位 = 8 - 2 = 6 → 2^6 - 2 = 62 > 60（满足主机数）
  4) 新子网掩码：255.255.255.192（1100 0000）
  5) 子网划分：
     子网1：212.16.56.0/26   （可用 212.16.56.1 ~ 212.16.56.62，广播 212.16.56.63）
     子网2：212.16.56.64/26  （可用 212.16.56.65 ~ 212.16.56.126，广播 212.16.56.127）
     子网3：212.16.56.128/26 （可用 212.16.56.129 ~ 212.16.56.190，广播 212.16.56.191）

答：
  新子网掩码：255.255.255.192
  子网2 网络号：212.16.56.64
  子网2 可分配IP：212.16.56.65 ~ 212.16.56.126
  子网2 广播地址：212.16.56.127
```

### 示例二：B 类网络子网划分

```
题目：147.0.0.0，至少需要900个物理网络，子网号至少多少位？子网掩码？
      对于 147.14.220.16，掩码 255.255.128.0，子网地址和主机号？

解答：
  1) 2^9 = 512 < 900 < 1024 = 2^10 → 子网号至少 10 位
  2) 子网掩码：255.255.255.192（在原 B 类 /16 基础上借 10 位 → /26）
     理论支持 2^10 = 1024 个子网
  3) 147.14.220.16 AND 255.255.128.0 = 147.14.128.0（子网地址）
     主机号：0.0.92.16
```

### 示例三：CIDR 路由聚合

```
题目：聚合 212.56.132.0/24、212.56.133.0/24、212.56.134.0/24、212.56.135.0/24

解答：
  132 = 10000100
  133 = 10000101
  134 = 10000110
  135 = 10000111
  前 22 位相同 → 聚合结果：212.56.132.0/22
```

### 易错点

- 子网掩码借位后，主机位减少，可用主机数 = `2^主机位 - 2`（减去网络号和广播地址）
- 子网号从 0 开始编号，不要遗漏第一个子网
- 广播地址 = 该子网所有主机位全为 1 的地址
- 计算片偏移时单位是 **8 字节**，即 `片偏移 = 数据偏移量 / 8`
- 路由聚合时要将变化的字节展开为二进制，找共同前缀

## 二、CRC 校验码计算

### 解题步骤

1. **确定生成多项式对应的二进制序列**：如 `G(X) = X^4 + X^3 + 1` → `11001`
2. **在数据位后补 0**：补 0 的个数 = 生成多项式的最高阶数（如最高阶为 4，补 4 个 0）
3. **模 2 除法**：用补 0 后的数据对生成多项式二进制序列做模 2 除法（异或运算）
4. **取余数**：余数即为 CRC 校验码（位数 = 最高阶数）
5. **拼接发送数据**：原始数据 + CRC 校验码 = 最终发送的数据

### 示例

```
题目：发送数据 11100010，生成多项式 G(X) = X^4 + X^3 + 1，求 CRC 校验码和最终发送数据。

解答：
  1) G(X) = X^4 + X^3 + 1 → 二进制：11001（5位，最高阶4）
  2) 数据后补 4 个 0 → 111000100000
  3) 模 2 除法：

     111000100000 ÷ 11001
     ─────────────────────
     111000100000
     11001
     ─────
       10101
       11001
       ─────
        11000
        11001
        ─────
          00110
          00000
          ─────
           01100
           00000
           ─────
            11000
            11001
            ─────
              0001 → 余数（注意高位补零）→ 1001

  4) CRC 校验码 = 1001
  5) 最终发送数据 = 11100010 + 1001 = 111000101001
```

### 易错点

- 生成多项式转二进制时，`X^n` 对应第 n 位为 1，常数项 1 = `X^0` 对应最低位为 1
- 模 2 除法是**异或**运算，没有借位和进位
- 余数位数必须等于生成多项式最高阶数，不足时**高位补零**
- CRC 校验码拼接到原始数据**后面**，不是前面
- 验证：接收方用（原始数据 + CRC）除以生成多项式，余数为 0 则无差错

## 三、路由器配置

### 3.1 接口 IP 地址配置

```
# 解题步骤：
# 1) 进入指定接口视图
# 2) 配置 IP 地址和子网掩码
# 3) 退出并查看配置

# 示例：为 R2 的 Serial 0/0/1 和 Serial 0/0/2 配置 IP
[R2] int s0/0/1
[R2-Serial0/0/1] ip address 172.16.12.2 255.255.255.252
[R2-Serial0/0/1] quit
[R2] int s0/0/2
[R2-Serial0/0/2] ip address 172.16.12.5 255.255.255.252
[R2] display ip interface brief    # 查看接口 IP 信息
```

### 3.2 静态路由配置

```
# 解题步骤：
# 1) 确定目标网络和子网掩码
# 2) 确定下一跳地址或出接口
# 3) 使用 ip route-static 命令配置

# 示例：R2 到达其他网段的静态路由
[R2] ip route-static 172.16.10.0 255.255.255.0 s0/0/1
[R2] ip route-static 172.16.11.0 255.255.255.0 s0/0/2
[R2] display ip route    # 查看路由表
```

### 3.3 默认路由配置

```
# 解题步骤：
# 1) 目标网络和掩码均为 0.0.0.0
# 2) 指定下一跳或出接口

# 示例：R1 配置默认路由
[R1] ip route-static 0.0.0.0 0.0.0.0 s0/0/1
```

### 3.4 RIP 动态路由配置

```
# 解题步骤：
# 1) 启动 RIP 进程
# 2) 指定版本（通常用 version 2）
# 3) 宣告直连网络（使用主网络号）

# 示例：R3 配置 RIP
[R3] rip 1
[R3-rip-1] version 2
[R3-rip-1] network 172.16.0.0
[R3-rip-1] quit
```

### 3.5 OSPF 动态路由配置

```
# 解题步骤：
# 1) 启动 OSPF 进程
# 2) 进入区域（通常用 area 0）
# 3) 宣告网络（使用反掩码 wildcard-mask）

# 示例：R3 配置 OSPF
[R3] ospf 1
[R3-ospf-1] area 0
[R3-ospf-1-area-0.0.0.0] network 172.16.11.0 0.0.0.255
[R3-ospf-1-area-0.0.0.0] network 172.16.12.4 0.0.0.3
[R3-ospf-1-area-0.0.0.0] quit
```

### 3.6 PC 静态 IP 配置说明

```
# PC1 静态 IP 地址配置示例
IP 地址：    172.16.10.1
子网掩码：   255.255.255.0
默认网关：   172.16.10.254    # 通常为所在网段的路由器接口地址
```

### 3.7 ACL 配置（高级）

```
# 解题步骤：
# 1) 创建 ACL 编号（基本 2000-2999，高级 3000-3999）
# 2) 编写规则（注意：如有 IPSec VPN，需先 deny 掉 VPN 关注的流量）
# 3) 在合适接口的合适方向应用 ACL

# 示例：NAT + IPSec 场景下的 ACL
[AR1] acl 3000
[AR1-acl-adv-3000] rule deny ip source 192.168.2.0 0.0.0.255 destination 172.16.1.0 0.0.0.255
[AR1-acl-adv-3000] rule permit ip source 192.168.1.0 0.0.0.255
[AR1-acl-adv-3000] rule permit ip source 192.168.2.0 0.0.0.255
```

### 易错点

- 接口配置时注意区分 `Serial`（串口）和 `GigabitEthernet`（以太网口），命令缩写不同
- 静态路由在**以太网接口**上必须指定**下一跳 IP 地址**，否则无法确定转发目标
- OSPF 的 `network` 命令使用**反掩码**（wildcard mask），不是子网掩码
  - 反掩码 = 255.255.255.255 - 子网掩码，如掩码 /24 → 反掩码 0.0.0.255
- RIP 的 `network` 只写主类网络号（如 `172.16.0.0`），不写子网
- 查看命令：`display ip interface brief`（接口信息）、`display ip route`（路由表）
- 默认路由的掩码是 `0.0.0.0`，不是 `255.255.255.255`
- ACL 部署原则：**尽量靠近源**，但不能影响正常通信

## 四、简答题模板

### 4.1 TCP/IP 分层结构及功能

```
答题模板：
TCP/IP 协议栈采用四层模型：

1. 应用层
   功能：为用户提供网络访问接口，定义应用间通信协议
   常见协议：HTTP、FTP、SMTP、DNS、DHCP
   作用：处理具体业务逻辑，如数据格式转换、用户认证

2. 传输层
   功能：端到端数据传输，确保可靠或高效传输
   核心协议：
   - TCP：面向连接、可靠传输（确认、滑动窗口、重传）
   - UDP：无连接、不可靠传输（效率高，适用于实时通信）
   关键机制：端口号实现多路复用

3. 网络层
   功能：路由与寻址，将数据包从源转发到目标
   核心协议：IP（寻址）、ICMP（故障诊断）、ARP（IP→MAC）
   关键机制：路由选择算法（OSPF、BGP）

4. 数据链路层
   功能：相邻节点间传输，处理 MAC 地址和错误检测
   核心协议：以太网协议、PPP
   关键机制：MAC 寻址、帧同步、CRC 校验
```

### 4.2 DNS 域名解析过程

```
答题模板：
1. 本地检查：计算机首先检查本地 DNS 缓存（含操作系统和浏览器缓存）
   → 若有未过期记录，直接返回结果，解析结束

2. 本地 DNS 服务器：若本地无缓存，向本地 DNS 服务器查询
   → 服务器检查自身缓存，有则直接返回

3. 根域名服务器：本地 DNS 向根域名服务器请求
   → 根服务器返回 .com 顶级域名服务器的 IP 地址

4. 顶级域名服务器：向 .com 顶级域名服务器请求
   → 返回 baidu.com 的权威域名服务器地址

5. 权威域名服务器：向权威域名服务器请求
   → 返回 www.baidu.com 的 IP 地址，并缓存

6. 返回结果：本地 DNS 将 IP 地址返回给主机，主机缓存并交给浏览器
```

### 4.3 ARP 协议安全隐患

```
答题模板：
1. ARP 欺骗（ARP Spoofing）
   攻击者伪造 ARP 响应包，将自己的 MAC 地址映射到目标 IP
   → 可导致中间人攻击（拦截、窃取、篡改通信数据）

2. ARP 泛洪（ARP Flooding）
   发送大量伪造 ARP 请求/应答包
   → 消耗交换机缓存资源，导致网络通信中断（DoS 攻击）

3. ARP 缓存投毒（ARP Cache Poisoning）
   篡改主机 ARP 缓存中的 IP-MAC 映射
   → 使数据包流向攻击者而非目标主机

4. 缺乏认证机制
   ARP 协议无加密或身份验证，任何主机均可发送 ARP 报文
   → 无法验证报文合法性，这是所有安全隐患的根本原因
```

### 4.4 OSPF 防止路由环路的机制

```
答题模板：

【区域内防环】
1. SPF 算法（Dijkstra）：
   - 每个路由器以自身为根，根据 LSA 生成全网拓扑图
   - 构建有向无环图（DAG），按距离递增顺序添加节点
   - 保证生成最短路径树（树状结构天然无环）

2. LSA 泛洪控制：
   - LSA 携带序列号和老化时间（默认 30 分钟）
   - 接收方比较序列号，丢弃旧版本 LSA
   - 校验和 + ACK 确保 LSA 可靠传播

【区域间防环】
3. 区域划分：
   - 非骨干区域只能与骨干区域（Area 0）交互路由信息
   - 非骨干区域间不允许直接传递路由
   - 骨干区域作为核心中转，形成树状路由结构
   - ABR（区域边界路由器）控制路由传播范围
```

### 4.5 T568A / T568B 线序标准

```
答题模板：
T568B 线序：橙白、橙、绿白、蓝、蓝白、绿、棕白、棕
T568A 线序：绿白、绿、橙白、蓝、蓝白、橙、棕白、棕

直通线：两端线序相同（均用 T568B 或均用 T568A）
  应用场合：连接不同类型设备，如 PC—交换机、路由器—交换机

交叉线：一端 T568A，另一端 T568B
  应用场合：连接相同类型设备，如 PC—路由器、交换机—交换机
```

### 4.6 私有地址与公有地址

```
答题模板：
私有地址：局域网内部使用，不直接在公共互联网上路由
```

### 4.7 数据报分片与重组

```
答题模板：

判断是否需要分片：
  条件1：IP 数据包大小 > 链路 MTU（如以太网 MTU 默认 1500 字节）
  条件2：DF 位 = 0（允许分片，若 DF=1 则直接丢弃）

分片计算步骤：
  1) 每个分片最大数据长度 = MTU - IP 首部长度（通常 20 字节）
  2) 分片数量 = ceil(原始数据长度 / 每片最大数据长度)
  3) 片偏移 = 数据偏移量 / 8（单位为 8 字节）
  4) MF 标志：中间分片 MF=1，最后一个分片 MF=0

示例：
  IP 首部 20 字节，数据 3000 字节，MTU = 820
  每片最大数据 = 820 - 20 = 800 字节
  分片数 = ceil(3000 / 800) = 4

  分片1：数据 800B，片偏移 0/8=0，MF=1
  分片2：数据 800B，片偏移 800/8=100，MF=1
  分片3：数据 800B，片偏移 1600/8=200，MF=1
  分片4：数据 600B，片偏移 2400/8=300，MF=0
```

### 4.8 路由表匹配（最长前缀匹配）

```
答题模板：
步骤：
  1) 将目的 IP 与各条路由的子网掩码进行 AND 运算
  2) 将结果与路由条目的网络号比较
  3) 选择匹配的路由中前缀最长的（掩码最长的）→ 最长前缀匹配原则
  4) 若多条同前缀路由匹配，比较优先级（值越小越优先）
  5) 若均无匹配，走默认路由（0.0.0.0/0）

示例：目的地址 192.4.153.18
  AND 255.255.255.128 → 192.4.153.0（无精确匹配该掩码的条目）
  AND 255.255.255.192 → 192.4.153.0（匹配到该路由，下一跳 205.35.8.26）
```

### 易错点（简答题通用）

- 回答要**分点作答**，逻辑清晰，使用编号
- 涉及协议名称时要写**全称**再写缩写，如"ARP（地址解析协议）"
- 线序题不要混淆 T568A 和 T568B（差异在 1-3、2-6 对调）
- DNS 过程要写出**完整的 6 步**，不能跳步
- 私有地址范围要写出**三类**及其对应的子网掩码
- 分片计算时片偏移单位是 **8 字节**，不要忘记除以 8
- 最长前缀匹配时，要按掩码**从长到短**依次匹配，找到第一个匹配即停止
